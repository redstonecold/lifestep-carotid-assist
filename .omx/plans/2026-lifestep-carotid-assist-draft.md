## 1. 프로젝트 주제

> 사용자 제작 라벨 기반 경동맥 초음파 내강 자동 추적 및 박동별 내경 측정·검토 지원 소프트웨어

### 한 문장 목표

경동맥 초음파 동영상에서 내강을 자동 추적하고, 박동별 최소·최대 내경과 변화량을 요약하며, 검토가 필요한 구간만 의료진에게 제시한다.

## 2. 문제 인식

경동맥 초음파 영상에는 수백 개의 프레임과 여러 번의 심장박동이 포함된다.

- 의료진이 모든 프레임의 혈관 경계를 직접 측정하기 어렵다.
- AI가 프레임별 숫자만 나열해도 다시 전부 확인해야 한다.
- 잡음과 탐촉자 움직임 때문에 일부 측정값이 크게 흔들린다.

따라서 전체 영상을 자동 분석하고, 여러 박동의 대표값과 오류 의심 구간만 보여주는 기능이 필요하다.

## 3. 분할을 하는 이유

**분할(Segmentation)**은 영상에서 경동맥 내강 영역을 픽셀 단위로 구분하는 작업이다.

```text
내강 자동 분할
→ 위·아래 내강 경계 검출
→ 프레임별 내경 계산
→ 박동에 따른 내경 변화 추적
```

분할 자체가 최종 목표는 아니다. 분할 결과를 이용해 반복 측정을 자동화하는 것이 목표다.

## 4. 의료적 활용과 범위

### 제공하는 기능

- 경동맥 내강 자동 추적
- 박동별 최소·최대 내경과 변화량 계산
- 여러 박동의 측정값 요약
- 측정 근거 프레임 제시
- 신뢰도가 낮은 구간 표시

### 제공하지 않는 판단

- 협착·플라크 진단
- 뇌졸중 위험 예측
- 동맥경화 진단
- 혈관 경직도·스트레스 판정

이 결과물은 진단 의료기기가 아니라 **연구용 측정·검토 보조 도구**다.

### FMD와의 차이

FMD는 주로 상완동맥을 촬영하면서 혈압 커프로 혈류를 막았다가 푼 뒤 혈관 확장을 측정하는 검사다.

현재 데이터에는 커프 전후 영상과 혈류 속도 정보가 없다. 따라서 FMD를 계산하지 않고 **경동맥의 박동별 내경 변화**를 측정한다.

### 사람 단위 분리

같은 사람의 프레임을 학습과 시험에 나누어 넣지 않는다. 비슷한 프레임이 양쪽에 섞이면 실제보다 성능이 높게 보이는 **데이터 누수**가 발생한다.

### 사람별 불균형 대응

P003은 AVI 7개(약 15,100프레임)로 다른 사람보다 프레임이 수십 배 많다. 반대로 P009~P011은 3초 클립뿐이라 사람당 약 115~230프레임이다.

- 사람별 초기 라벨 수를 비슷하게 맞춘다.
- 비슷한 연속 프레임은 반복 사용하지 않는다.
- 사람을 먼저 선택한 뒤 프레임을 선택하는 균형 추출을 사용한다.
- 전체 프레임 평균과 사람별 성능을 함께 제시한다.

프레임 수보다 서로 다른 사람과 촬영 조건의 다양성을 우선한다.

### 동맥과 정맥이 함께 보이는 프레임

**포함하고 경동맥만 칠한다. 정맥은 배경으로 둔다.**

- 실제 검사 영상에도 정맥이 자주 함께 보인다.
- 동맥만 보이는 프레임으로 학습하면 실제 영상에서 정맥을 동맥으로 잡을 수 있다.
- 어느 쪽이 동맥인지 확신할 수 없는 프레임만 X(제외)로 둔다(7절).

### 학습·검증·시험 구성 (2026-11-10 변경: 학습 9 · 검증 1 · 시험 1)

**검증과 시험의 차이**

| 구분 | 언제 쓰나 | 모델 선택에 영향 |
|---|---|---|
| 검증 | 학습 중 매 epoch 끝, 그리고 설정 비교 | 받는다. 가장 좋은 epoch·설정을 검증 점수로 고르므로 모델이 검증자에게 간접적으로 맞춰진다 |
| 시험 | 모든 결정이 끝난 뒤 한 번 | 받지 않는다. 처음 보는 사람에 대한 정직한 성능 추정 |

| 장점 | 내용 |
|---|---|
| 장비 다양성 | 사람은 11명으로 늘었지만 장비는 여전히 2종(AVI 장비, E-CUBE 15)뿐이다. TIFF는 5종 이상의 장비 영상이 섞여 있다 |
| 일반화 | 밝기·해상도·화면 구성이 다른 영상을 보면 새 장비 영상에서 덜 흔들린다 |
| 낮은 비용 | 정지영상이라 프레임 추출이 필요 없고, 라벨 수만 정하면 된다 |

**검증·시험에 넣지 않는 이유:** 이미지별 대상자를 알 수 없어 사람 단위 분리를 확인할 수 없다. 학습 전용으로는 누수가 생기지 않는다. 인터넷 이미지 속 사람이 우리 검증·시험 대상자일 가능성이 사실상 없기 때문이다.

| 단계 | 할 일 | 기준 |
|---|---|---|
| 1. 선별 | 500장 축소판을 묶음별로 훑어 사용 후보 고르기 | 경동맥 종단면, 위·아래 벽이 보임. 횡단면·다른 부위·심한 잡음 제외 |
| 2. 중복 제거 | 이미지 유사도 해시로 거의 같은 사진 제거 | 같은 장면은 1장만 |
| 3. 전처리 | 화면 글자·눈금 영역을 잘라내고 흑백으로 변환 | 우리 영상과 같은 처리 |
| 4. 크기 맞춤 | 화면 눈금이 있으면 0.1mm/px로 재표본화, 없으면 크기 변화 증강으로 대응 | mm 정보가 없어도 분할 학습에는 문제없음 |
| 5. 라벨 | 묶음(장비)당 5~10장, 총 25~50장 | 우리 영상과 같은 A/B/C 기준, 경동맥만 칠함 |
| 6. 학습 비중 | 균형 추출에서 TIFF 전체를 1개 그룹으로 취급 | TIFF가 학습을 지배하지 않게 함 |
| 7. 효과 확인 | TIFF 포함·미포함 두 모델을 검증(P006)으로 비교 | 검증 Dice·내경 오차가 같거나 좋아지면 유지 |

- 우선순위: 동영상 라벨 다음. 라벨 시간이 부족하면 가장 먼저 뺀다.
- 내경(mm) 평가에는 사용하지 않는다.
- 이용 범위: 내부 연구·교육용 학습에만 쓰고, 원본 이미지는 발표 자료나 외부에 게시하지 않는다.
- `tech_401`~`500` 묶음은 영상 모양이 다른 묶음과 달라 선별 단계에서 사용 여부를 따로 판단한다.

### 데이터 세트 A/B/C/F (2026-11-10 변경)

| 세트 | 기준 | 마스크 | 학습 | 내경 평가 |
|---|---|---|---|---|
| A | 위·아래 벽의 **내벽 흰 띠**까지 선명하고, 혈관이 화면 좌우 끝까지 이어짐 | 내강 전체 | 사용 | 사용 |
| B | 내강은 보이지만 내벽 흰 띠가 안 보이거나 흐림 | 보이는 내강 | 사용 | 따로 집계(참고값) |
| C | 위·아래 벽은 보이지만 혈관이 **화면 중간에서 끝나거나 끊겨** 좌우 끝까지 이어지지 않음(측정 가능한 길이가 짧음) | 보이는 내강만. 끊긴 너머는 추측하지 않음 | 사용 | 중앙 안정 구간만 사용 |
| F | 위·아래 벽 중 **한쪽이 안 보이거나**, 경동맥이 **아예 안 보임**(횡단면·탐촉자 이동·검출 불가 영상 포함) | 확실히 보이는 내강만. 확신할 수 있는 내강이 없으면 **빈 마스크** | **사용(필수)** | 제외. 검출 불가 판정 평가에 사용 |
| X | 동맥·정맥 구분을 확신할 수 없음 | - | 제외 | 제외 |

- 여러 조건에 걸리면 **더 나쁜 쪽**으로 분류한다(F > C > B > A).
- **F세트를 학습에 넣는 이유**: 실제 영상에는 탐촉자 이동·횡단면·혈관이 안 보이는 구간이 있다. 혈관이 보이는 프레임만 배우면 모델은 어떤 영상에서든 무언가를 칠하려 한다. F세트로 "칠할 것이 없을 때는 칠하지 않기"를 배워야 소프트웨어가 `자동측정 불가`를 정확히 표시할 수 있다.
- X는 삭제하지 않고 `검토 필요` 표시 시험 사례로 보관한다.

> **C 기준 확정(2026-11-10)**: 처음에는 "혈관 좌우 끝이 화면 밖이면 C"로 정했으나, 종단면 프레임은 대부분 혈관이 화면 좌우 끝까지 이어져 이 정의로는 A가 거의 없어진다. batch01 처음 10장을 실제로 분류해 보니 화면 끝까지 이어진 선명한 혈관은 A, 화면 안에서 끝나거나 끊긴 혈관은 C로 나뉘었고(A 4 · C 4 · X 2), 이 구분을 정식 기준으로 확정했다.

## 8. 화면 끝까지 이어진 혈관과 중간에서 끊긴 혈관

종단면에서는 혈관이 화면 좌우 끝까지 이어지는 경우가 대부분이다.

- **화면 좌우 끝까지 이어진 혈관**: 화면 밖은 추측하지 않고 보이는 내강을 화면 끝까지 그린다. 내벽 흰 띠가 선명하면 A, 흐리면 B.
- **화면 중간에서 끝나거나 끊긴 혈관(C)**: 보이는 부분만 그린다. 측정 가능한 길이가 짧으므로 학습에는 쓰고, 내경은 보이는 구간의 중앙에서만 잰다(2026-11-10 확정).
- 내경은 영상 가장자리가 아닌 중앙의 안정된 구간에서 측정한다.

C를 학습에 넣어야 혈관이 길게 보이는 영상에만 익숙해지는 것을 막을 수 있다.

위쪽 또는 아래쪽 경계가 잘려 두 경계 사이 거리를 알 수 없으면 F세트로 분류하고 내경 측정에서는 제외한다.

| 4 | 흑백 변환 | 1채널 | 초음파는 흑백, WMV·DICOM 색 정보는 의미 없음 |
| 5 | 크기 통일 | 모든 영상을 0.1mm/px로 재표본화 | 장비가 달라도 혈관이 같은 크기로 보임 |
| 6 | 밝기 정규화 | 영상마다 평균 0, 표준편차 1 (증강 **뒤**에 적용) | 장비별 밝기 차이 감소. 그래서 전체 밝기·대비 증강은 효과가 거의 없음(`증강 파라미터`) |
| 7 | 마스크 처리 | 영상과 같은 크롭·재표본화, 최근접 보간 | 경계가 흐려지지 않고 위치 일치 |
| 8 | 학습 입력 | 256×256 크롭(2/3 무작위, 1/3 내강 중심) + 증강 | 내강이 없는 크롭만 계속 나오는 것 방지. nnU-Net 전경 과표집 33%와 같은 방식 |
| 9 | 추론·측정 | 영상 전체 입력(32의 배수로 패딩) → 예측 → 원래 좌표로 되돌려 mm 계산 | 측정 오차 최소화 |

- **압축 차이**: P004~P008 DICOM은 JPEG 손실압축, P009~P011은 비압축이다. 압축 잡음 차이를 줄이기 위해 증강에 약한 흐림을 포함하고, 검증 결과를 그룹별로도 본다.
- **대비 강조(CLAHE)**: 기본 전처리에 넣지 않는다. 흐린 경계는 또렷해지지만 잡음도 커지므로 증강 옵션으로만 두고 1차 탐색에서 1회 비교한다.
- TIFF는 6절 `TIFF 활용 계획`의 전처리를 따른다.

### 기본 모델

- U-Net + ResNet34 사전학습(ImageNet)
- 입력: 초음파 단일 프레임 / 출력: 원래 해상도의 경동맥 내강 마스크
- 실행: PyTorch MPS로 Apple GPU 사용

**사전학습**은 일반 이미지에서 배운 특징을 시작점으로 사용하는 방법이다.

#### 근거의 한계와 확인 방법

- 위 연구들은 데이터 규모·장비·목표(내강·벽·다른 장기)가 이 프로젝트와 다르다. 따라서 **우리 데이터에서 직접 확인**한다.
- 하이퍼파라미터 1차 탐색에 **사전학습 vs 무작위 초기화** 1회를 추가해, 사전학습 효과를 검증(P006)으로 보인다.
- 시간이 남으면 같은 조건으로 HRNet-W18을 1회 학습해 선택 이유를 실험으로 확인한다.

### 학습 루프 구조: Dataset 2개 · loop 2개 (2026-11-10)

```text
train Dataset : 학습 9명, A·B·C·F, 증강 O, 256 크롭, 사람별 균형 추출
valid Dataset : 검증 P006, A·B·C·F, 증강 X, 전체 프레임(32 배수 패딩)

for 설정 in 설정 목록:                     ← 자기 전에 켜 두는 바깥 루프
    for epoch in 1..80:
        ① train loop : 학습 모드, 증강, 손실 계산 → 역전파
        ② valid loop : 평가 모드, 역전파 없음, 검증 지표 전부 계산
        epoch 결과를 CSV에 한 줄 기록
        valid Dice 최고면 체크포인트 저장 / 15 epoch 정체 시 중단
```

- 두 Dataset은 같은 코드에서 `split='train'` / `split='valid'`로 만들고, 사람 단위로 완전히 분리된다.
- train loop: epoch당 9명 × 50장 = 450장(배치 8, 57스텝).
- valid loop: 검증 라벨 약 40장을 매 epoch 한 번씩. 실제 추론과 같은 방식(전체 프레임)으로 잰다.
- 자기 전에 `caffeinate -i python -m src.train --sweep` 한 줄로 시작하고 아침에 결과표를 본다. 중간에 끊겨도 다시 실행하면 이어서 돈다(`실행 방식`).

### 손실 함수 처리 (2026-11-10)

**문제:** F세트에는 빈 마스크가 많다. 이미지마다 Dice를 따로 계산하면 정답이 빈 이미지에서 0÷0이 되어 값이 튀고, 아주 작은 오검출에도 손실이 1로 뛴다.

| 항목 | 처리 | 이유 |
|---|---|---|
| 기본 손실 | Dice + BCE (1:1) | nnU-Net 기본 손실 |
| 비교 후보 | Dice + Focal (γ=2) | 흐린 경계처럼 어려운 픽셀에 집중. 1차 탐색 1단계에서 비교 |
| Dice 계산 단위 | 배치 8장의 픽셀을 합쳐 한 번 계산(batch Dice, smooth 1). 현재 코드 방식 유지 | 빈 마스크가 섞여도 분모가 0이 되지 않음 |
| F세트 빈 마스크 | BCE(또는 Focal)가 "아무것도 칠하지 않기"를 학습시킨다. batch Dice에도 오검출 픽셀이 분모로 들어가 벌점이 된다 | 오검출 억제 |
| 세트별 가중치 | 픽셀 손실에 A 1.0 · B 0.7 · C 1.0 · F 1.0 | B는 경계가 불확실하므로 덜 믿는다. 0.7은 판단값이라 1차 탐색에서 전부 1.0과 1회 비교 |
| 손실 기록 | 매 epoch **train loss와 valid loss를 모두** CSV에 기록하고 곡선을 저장 | train↓ valid↑면 과적합 신호 |
| 최선 epoch·조기 종료 기준 | 손실이 아니라 **valid Dice(A·B·C)** | 손실값은 가중치·손실 종류에 따라 크기가 달라 설정끼리 비교할 수 없음 |
| 발산 처리 | 손실이 NaN이거나 처음 10 epoch 안에 3 epoch 연속 증가하면 그 설정을 멈추고 결과표에 `발산` 기록 | 밤새 도는 루프가 한 설정에 묶이지 않게 |

### 증강 파라미터 (학습 Dataset에만, 2026-11-10)

**먼저 고칠 점:** 밝기 정규화(영상마다 평균 0·표준편차 1)가 증강 뒤에 있어서, 영상 전체에 같은 값을 곱하거나 더하는 밝기·대비 증강은 정규화에서 거의 지워진다. 현재 코드의 밝기·대비 ±10%는 사실상 효과가 없다. 그래서 정규화 뒤에도 남는 **감마(비선형)**와 **깊이별 밝기(부분 변화)**를 밝기 증강의 중심으로 둔다.

| 분류 | 증강 | 약 | **중(기본)** | 강 | 확률 | 근거 |
|---|---|---|---|---|---:|---|
| 기하 | 좌우 반전 | ○ | ○ | ○ | 0.5 | 장비·촬영자마다 머리 방향이 좌우로 다름. 해부학적으로 실제 가능 |
| 기하 | 상하 반전 | 안 씀 | 안 씀 | 안 씀 | - | 초음파는 위쪽이 피부(탐촉자) 쪽. 뒤집으면 실제로 나올 수 없는 영상 |
| 기하 | 회전 | ±5° | ±15° | ±25° | 0.5 | P007처럼 탐촉자가 기운 영상 대응. batch02 라벨에서 혈관 기울기 분포를 재서 강 범위를 확인 |
| 기하 | 크기 | ±10% | ±15% | ±25% | 0.5 | 0.1mm/px로 맞춰도 사람마다 혈관 지름(약 5~9mm)이 다름. nnU-Net 기본 0.7~1.4 |
| 기하 | 가로·세로 비율 늘리기 | 안 씀 | ±5% | ±10% | 0.3 | 장비별 화면 비율 차이. 크게 늘리면 실제와 다른 혈관 모양이 되므로 작게 |
| 기하 | 위치 이동 | 무작위 크롭으로 대체 | | | - | 별도 증강 불필요 |
| 기하 | 탄성 변형 | 안 씀 | 안 씀 | 안 씀 | - | 곧은 혈관 벽이 휘어 내경이 실제와 달라짐 |
| 밝기 | 감마 | 0.8~1.25 | 0.7~1.5 | 0.6~1.7 | 0.3 | nnU-Net 기본 0.7~1.5. 정규화 뒤에도 남는 비선형 변화 |
| 밝기 | 깊이별 밝기(위→아래 기울기) | 안 씀 | ×0.8~1.2 | ×0.7~1.3 | 0.3 | 장비 깊이 이득(TGC) 설정 차이 흉내. AVI 0007처럼 아래가 어두운 영상 |
| 밝기 | 전체 밝기·대비 | ±10% | ±20% | ±30% | 0.5 | 정규화로 대부분 지워지지만 흰색 포화 효과는 남음. 비용이 없어 유지 |
| 화질 | 가우시안 잡음 | 안 씀 | σ 0~0.05 | σ 0~0.1 | 0.15 | nnU-Net 기본(p 0.1). σ는 0~1 밝기 기준 |
| 화질 | 스펙클(곱셈) 잡음 | 안 씀 | σ 0~0.1 | σ 0~0.2 | 0.2 | 초음파 고유 잡음 형태 |
| 화질 | 흐림 | 안 씀 | σ 0.5~1.0 | σ 0.5~1.5 | 0.2 | nnU-Net 기본 σ 0.5~1.0, p 0.2 |
| 화질 | JPEG 압축 | 안 씀 | 품질 50~95 | 품질 30~95 | 0.3 | P004~P008 손실압축과 P009~P011 비압축의 차이 대응 |

- 적용 순서: 재표본화 → 기하(이미지·마스크 함께, 마스크는 최근접 보간, 빈 곳은 0) → 256 크롭 → 밝기 → 화질 → 정규화.
- 검증·시험·추론에는 증강을 쓰지 않는다.
- 약·중·강은 1차 탐색 2단계에서 비교하고, 그 전 단계(1단계)는 **중**으로 돌린다.
- 수치 근거: 종류와 감마·잡음·흐림·크기 범위는 nnU-Net 기본값, 회전·비율·깊이별 밝기·JPEG 수치는 우리 데이터 관찰에 따른 판단값이며 탐색으로 확인한다.

### 검증 지표 (valid loop에서 매 epoch 계산, 2026-11-10)

원칙은 두 가지다.

- **보고는 필요한 만큼**: 선행연구 비교와 측정 목적에 필요한 14종을 보고서에 싣는다. 다른 지표로 알 수 있거나(중복) 오해 소지가 큰 10종(특이도·정확도·면적 유사도·HD·NSD·RMSE·Pearson r·AUC 등)은 뺀다(2026-11-10).
- **원자료 저장**: 프레임마다 혼동행렬 값(TP·FP·FN·TN), 경계 거리, 내경을 저장한다. 뺀 지표가 필요해지면 재학습 없이 다시 계산한다.
- **결정은 좁게**: 모델·설정 선택에 쓰는 지표는 미리 3개(Dice · F 오검출률 · 내경 MAE)로 고정한다. 결과를 본 뒤 유리한 지표를 고르는 편향을 막기 위해서다.

모든 지표는 세트(A·B·C·F)별로도 따로 계산한다.

| 분류 | 지표 | 대상 세트 | 결정 | 보고 |
|---|---|---|---|---|
| 겹침 | **Dice** | A·B·C | **최선 epoch·1차 선별** | O |
| 겹침 | IoU | A·B·C | | O (선행연구 비교) |
| 겹침 | 정밀도(Precision) | A·B·C | | O (과분할 진단) |
| 겹침 | 민감도(Recall) | A·B·C | | O (과소분할 진단) |
| 경계 | HD95 (mm) | A·B·C | 동점 처리 | O |
| 경계 | ASSD 평균 경계 거리 (mm) | A·B·C | | O |
| 측정 | **내경 MAE (mm)** | A·C(중앙 구간) | **최종 선택** | O |
| 측정 | 내경 편향 (mm) | A·C | | O |
| 측정 | Bland-Altman 95% 일치 한계 | A·C | | O (표 + 그림) |
| 측정 | ICC(2,1) 절대일치 | A·C | | O |
| 측정 | 박동별 변화량 MAE (mm) | P004·P006 박동 프레임 | | O (15절) |

| 기준선 | 반복 라벨(같은 프레임 재라벨)의 같은 지표 | A·C 20장 | | O (사람 간 일치 수준과 AI 비교) |

- 10mm²는 혈관 1cm 길이 × 1mm 폭 정도로, 정상 내강 넓이(약 200mm² 이상)의 5% 수준이다. 판단값이다.
- B세트 내경 오차는 참고값으로 따로 보고하고 선택 기준에는 쓰지 않는다.
- 계산 시점: 프레임 간 변동을 뺀 모든 지표를 매 epoch valid loop에서 계산한다. 검증이 약 40장이라 경계 거리 계산을 포함해도 수 초면 된다. 프레임 간 변동은 영상 전체를 추론해야 해서 최종 모델에서만 계산한다.

| 표 1 | 분할 성능 | 겹침·경계 지표 전체. 평균 ± SD, 중앙값 [IQR], 95% 신뢰구간 |
| 표 2 | 측정 일치도 | MAE · 편향 · 일치 한계 · ICC · 변화량 MAE |
| 표 3 | 검출 성능 | F 오검출률 · 미검출률 |
| 표 4 | 세트별 성능 | 표 1~3을 A·B·C·F로 나눔 |
| 표 5 | 사람별·그룹별 성능 | 교차검증 9명 각각, 긴 DICOM / 3초 클립 / WMV |
| 표 6 | AI vs 반복 라벨 | 같은 지표로 AI-사람 차이와 사람-사람 차이 비교 |
| 그림 1 | Bland-Altman 그림 | 내경 차이 vs 평균, 편향선, 일치 한계선 |
| 그림 2 | 내경 산점도 | AI vs 수동, y = x 기준선 |
| 그림 3 | 사람별 Dice·MAE 상자그림 | 교차검증 |
| 그림 4 | 학습 곡선 | epoch별 train/valid loss, valid Dice |
| 그림 5 | 결과 예시 | 세트별 좋은 예·나쁜 예 마스크 겹쳐 보기 |

- 신뢰구간은 bootstrap(2,000회)으로 구한다. 교차검증은 사람 단위로 재표집해 같은 사람의 프레임끼리의 상관을 반영한다.
- 모든 표에 표본 수(사람 수, 프레임 수)를 함께 적는다.

### 하이퍼파라미터 탐색

**하이퍼파라미터**는 학습 전에 사람이 정하는 설정값이다. 여러 설정 세트를 만들어 루프로 자동 학습하고, 검증 결과로 하나를 고른다.

#### 구성 원칙

1. 모든 조합(약 72회)을 돌리지 않는다. 영향이 큰 항목부터 정하고 고정한 뒤 다음 단계로 넘어간다.
2. 영향이 큰 항목(학습률·손실함수·증강·입력 크기)만 탐색하고 나머지는 표준값으로 고정한다.
3. 검증 대상자가 P006 1명뿐이므로 세트 수를 일부러 줄인다. 많이 시험할수록 검증 1명에만 우연히 맞는 설정을 고를 위험이 커진다.
4. 같은 설정도 실행마다 결과가 달라지므로 상위 설정은 시드를 바꿔 3회 반복한다.

#### 1차 탐색: 1단계 라벨(batch01+batch02) 완료 후, 23회

학습 9명 전체가 1차부터 들어간다. batch02 라벨 전에 batch01만으로 1~2회 돌려 루프 코드만 미리 검증한다(성능 수치는 보고하지 않음).

| 단계 | 바꾸는 항목 | 후보 | 횟수 | 근거 |
|---|---|---|---:|---|
| 1 | 학습률 × 손실함수 | 3e-4·1e-3·3e-3 × Dice+BCE·Dice+Focal | 6 | 학습률이 가장 큰 영향. Focal은 흐린 경계 픽셀에 집중 |
| 2 | 증강 강도 × 입력 크기 | 약·중·강 × 256·384 | 6 | 증강은 장비·압축 차이 과적합 방지. 384는 벽이 뭉개지는지 확인 |
| 3 | 사전학습 활용 | 전체 학습 · 인코더 5 epoch 고정 후 전체 학습 | 2 | 적은 데이터에서 사전학습 특징 보존 여부 |
| 4 | 재현성 | 상위 2개 × 시드 3회 | 6 | 우연히 좋게 나온 설정 제거 |
| 5 | 대비 강조 | 최종 설정 + CLAHE 증강 | 1 | 흐린 경계 개선 효과 확인 |
| 6 | 사전학습 효과 | 최종 설정 + 무작위 초기화 | 1 | 모델 선택 근거를 우리 데이터로 확인 |
| 7 | 세트 가중치 | 최종 설정 + B 가중치 1.0 | 1 | B 0.7이 실제로 도움이 되는지 확인 |

- 1단계는 증강 **중**, 세트 가중치 B 0.7로 돌린다.
- 증강 약·중·강의 값은 위 `증강 파라미터` 표를 따른다.

#### 후보값 선택 근거

| 항목 | 후보 | 근거 | 근거 유형 |
|---|---|---|---|
| 학습률 | 1e-3 | Adam 제안 논문의 권장 기본값 (Kingma & Ba, 2015) | 문헌 |
| 학습률 | 3e-4, 3e-3 | 학습률은 로그 간격 탐색이 원칙 (Bergstra & Bengio, 2012). 1e-3 중심으로 약 3배 간격 | 문헌 원칙 + 판단 |
| 손실 | Dice+BCE | nnU-Net 기본 손실 (Isensee et al., 2021) | 문헌 |
| 손실 | Dice+Focal | 어려운 픽셀에 가중치를 주는 손실 (Lin et al., 2017). 흐린 경계 개선은 추정 | 문헌 + 추정 |
| 증강 종류 | 밝기·대비·감마·크기·회전·잡음·흐림 | nnU-Net 기본 증강 목록 | 문헌 |
| 증강 세기 | `증강 파라미터` 표의 약·중·강 | 감마·잡음·흐림·크기는 nnU-Net 기본값, 회전은 P007 기운 촬영을 보고 ±15°(중)로 설정 | 문헌 + 데이터 관찰 + 판단 |
| 입력 크기 | 256, 384 | 0.1mm/px 기준 영상 약 350×270~500×350, 혈관 지름 약 70px. 256은 혈관이 충분히 들어가는 크기, 384는 AVI 화면 거의 전체 | 우리 데이터 |
| 인코더 고정 | 5 epoch | 사전학습 모델을 단계적으로 푸는 기법. 수치는 판단 | 관례 + 판단 |
| 시드 반복 | 3회 | 결과 편차를 보기 위한 최소 횟수 | 관례 |
| 최적화 | AdamW 1e-4, 코사인 감소 | 널리 쓰이는 표준 조합 (Loshchilov & Hutter) | 문헌·관례 |
| Epoch | 최대 80, 15회 정체 시 중단 | 실제 횟수는 조기 종료가 결정. 상한 수치는 판단 | 판단 |
| 배치 | 8 | M2 실측 GPU 메모리 2.3GB(입력 384도 3.6GB)로 16GB에 여유 | 실측 |

- 출발점은 문헌 기본값, 탐색 범위는 로그 간격 원칙, 최종 값은 실험 결과로 정한다.
- 판단으로 정한 수치는 탐색 결과로 검증한다.

#### 2차 탐색: 3단계 라벨(초안 수정) 완료 후, 20~30회

| 시점 | 횟수 | 목적 |
|---|---:|---|
| 1차 | 23 | 큰 방향 잡기 + 루프 코드 검증 |
| 2차 | 20~30 | 1차 상위 설정 주변을 촘촘히 탐색(예: 학습률 5e-4·2e-3, 증강×손실 조합, 인코더 ResNet18·34·50, 상위 3개 × 시드 3회) |

1차를 약 20회로 제한하는 이유:

- 시간 때문이 아니다. 루프는 중단·재개가 가능하다.
- 검증이 1명이라 세트를 늘릴수록 선택 결과를 믿기 어렵다.
- 3단계에서 라벨이 늘면 최적 설정이 달라질 수 있다.

2차를 기존 30~40회에서 줄인 이유: 모든 대상자가 이미 도착해 1차부터 전체 학습 데이터로 탐색하므로, 2차는 라벨 증가 후 확인 성격이다.

설정이 확정되면 15절의 **교차검증**(필수)으로 최종 설정이 검증 1명에만 맞춘 것이 아닌지 확인하고, **학습 곡선**으로 데이터 양이 충분한지 확인한다.

시험 전용 P004는 1·2차 탐색 어디에도 사용하지 않고 마지막에 한 번만 평가한다.

#### 고정값

| 항목 | 값 | 근거 |
|---|---|---|
| 모델 | U-Net + ResNet34 사전학습 | 확정 모델 |
| 최적화 | AdamW, weight decay 1e-4 | 표준 |
| 학습률 스케줄 | 짧은 워밍업 후 코사인 감소 | 표준, 시작 학습률만 탐색 |
| Epoch | 최대 80, 검증 15회 정체 시 중단 | 조기 종료가 결정 |
| 배치 | 8 | M2 실측: 입력 256에서 GPU 메모리 2.3GB, 1스텝 0.33초 |
| 정밀도 | FP32 | MPS에서 FP16 불안정 가능 |
| 데이터 분할 | 학습 P001·P002·P003·P005·P007·P008·P009·P010·P011(+TIFF), 검증 P006, 시험 P004 | 6절 구성 |
| 사용 세트 | 학습·검증 모두 A·B·C·F (X 제외) | 7절 |

#### 선택 기준

1. epoch 선택: 설정마다 valid Dice(A·B·C)가 가장 높은 epoch의 체크포인트를 쓴다
2. 검증 Dice가 최고값보다 0.01 이상 낮은 설정은 탈락
3. F 오검출률이 20%를 넘는 설정은 탈락(검출 불가 프레임 5장 중 1장 넘게 칠하면 `자동측정 불가` 표시를 믿을 수 없음, 판단값)
4. 남은 설정 중 내경 MAE(A·C)가 가장 작은 설정 선택
5. MAE 차이가 0.02mm 이내면 HD95가 작은 쪽, 그래도 같으면 더 단순하고 빠른 설정 선택

#### 실행 방식

- **M2 실측(2026-11-03, 실제 프레임, `tools/bench_real.py`)**: 학습 연산은 모두 GPU(MPS)에서 실행되고 CPU 대체 실행 없이 동작함을 확인. epoch = 학습 사람 수 × 50장이므로 epoch 시간은 라벨 수가 아니라 사람 수로 정해진다. 아래 실측은 7명(44스텝) 기준이며, 9명이면 57스텝으로 약 1.3배가 된다.

| 구간 | epoch당 | GPU 1스텝 | 데이터 준비(CPU) |
|---|---:|---:|---:|
| 처음 약 12분(epoch 1~40) | 약 17초 | 0.33초 | 약 2.5초 |
| 발열 이후(epoch 42~60) | 약 25~27초 | 0.47~0.54초 | 약 3~5초 |

- MacBook Air는 팬이 없어 **연속 학습 약 12분 뒤부터 GPU가 약 50% 느려진다.** 시간 추정은 발열 이후 속도(epoch당 약 26초)로 잡는다.
- 9명 기준 epoch당 약 35초(발열 후 학습 57스텝 약 30초 + 데이터 준비 + valid loop 40장 약 2초). 1회 학습(평균 약 50 epoch 가정) 약 29분. 추정값이므로 첫 실행에서 다시 잰다.

| 작업 | 횟수 | 예상 시간 |
|---|---:|---:|
| 1차 탐색 | 23 | 약 11시간 → 밤 2회 |
| 2차 탐색 | 20~30 | 약 10~15시간 → 밤 2회 |
| 교차검증(9:1 순환) | 9 | 약 4.5시간 |
| TIFF 비교 · 학습 곡선 | 4 | 약 2시간 |
| 합계 | | 약 28~33시간 → 밤 4~6회 |

- 발열 대책: 전원 연결, 덮개 열고 받침대 위에 두기, 다른 무거운 작업과 동시에 돌리지 않기. 그래도 부족하면 탐색 횟수(1차 23회)를 먼저 줄인다.
- 추론은 프레임당 29ms(발열 후 43ms) → AVI 1개(약 2,200프레임) 약 1~1.6분, 전체 영상 약 19,700프레임 약 10~14분.
- **중단·재개 가능**: 세트가 끝날 때마다 결과표(CSV)에 저장하고, 다시 실행하면 끝난 세트는 건너뛴다. 학습 중인 세트는 epoch마다 체크포인트를 저장해 끊긴 지점부터 이어서 학습한다.
- 여러 밤에 나눠서 실행할 수 있다. 밤새 실행할 때는 `caffeinate`로 Mac 잠자기를 막는다.
- 결과표에 데이터 버전을 기록하고, 라벨이 바뀐 뒤에는 이어 돌리지 않도록 경고한다.
- 루프가 끝나면 세트별 결과표와 그래프가 자동 저장되어 발표 근거로 사용한다.
- 확정 설정으로 TIFF 포함·미포함 비교(2회)를 함께 실행한다.
- 확정 설정으로 학습 곡선 2회(라벨 25%·50%, 100%는 최종 모델 재사용)와 교차검증 9회를 하룻밤에 함께 실행한다.

## 12. 내경 측정과 박동 분석

분할 마스크에서 다음 과정을 수행한다.

1. 내강의 중심선을 구한다.
2. 중심선에 수직인 방향으로 위·아래 경계 거리를 잰다.
3. 중앙의 안정된 구간에서 대표 내경을 계산한다.
4. 프레임별 내경 변화 그래프를 만든다.
5. 반복되는 변화를 심장박동 단위로 묶는다.

### 박동별 결과

- 최소 내경
- 최대 내경
- 내경 변화량
- 여러 박동의 평균 또는 중앙값

AVI 화면에 ECG가 있으면 박동 구분에 우선 사용한다. ECG가 없으면 내경 변화 신호의 반복 주기를 이용한다.

- ECG가 있는 사람은 P003뿐이다. 나머지 10명은 모두 내경 신호 주기로 박동을 나눈다.
- 따라서 **P003에서 ECG 기준 박동과 내경 신호 기준 박동을 비교**해 ECG 없는 방식의 정확도를 먼저 확인한다.
- 긴 DICOM(P004~P008, 대부분 15초)은 박동이 10회 이상 들어 있어 박동 요약 시연에 적합하다. 3초 클립(P001·P002·P009~P011)은 박동이 2~4회뿐이라 박동 요약은 참고용으로만 쓴다.

### 검토가 필요한 구간

- 마스크가 끊긴 경우
- 내경이 갑자기 변한 경우
- 다른 박동과 차이가 큰 경우
- 분할 신뢰도가 낮은 경우

## 13. 측정 단위

의료진용 결과는 mm를 기본으로 한다.

| 영상 | 보정값 | 근거 | 상태 |
|---|---|---|---|
| WMV (P001·P002) | 0.0694mm/px | 같은 검사의 DICOM 보정 정보. WMV와 DICOM 화면 위치가 정확히 일치함(어긋남 0픽셀) | 확정 |
| DICOM (P004~P011) | 0.0694mm/px | 각 파일 DICOM 헤더(초음파 영역 PhysicalDelta 0.00694cm) | 확정 |
| AVI (P003) | 0.078mm/px | 깊이 눈금 64px 간격을 5mm로 가정 | 눈금 간격 확인 필요 |

- E-CUBE 15 영상 10명은 모두 헤더 보정값이 있다. 보정 미확정은 P003 AVI 하나만 남는다.
- 보정값은 파일마다 헤더에서 읽고, 값이 다르면 경고한다.
- 화면 깊이 표기(D 3.5cm)로 WMV 보정값을 한 번 더 검증한다.
- 보정 근거가 없으면 임의로 mm를 만들지 않는다.

보정할 수 없는 경우 `mm 산출 불가`로 표시하고 상대 변화만 참고값으로 제공한다.

### AVI 보정이 끝내 확인되지 않을 때

눈금 간격은 촬영 담당자도 모르는 상태다(2026-11-03). 그래서 다음 순서로 처리한다.

1. ~~AVI 화면의 깊이 표기로 확인~~ → 확인 결과 화면에는 `29 Hz`, 깊이 눈금, ECG만 있고 깊이 숫자 표기가 없다(2026-11-03). 이 방법은 쓸 수 없다.
2. 따라서 **간접 확인**을 한다. 모델이 완성된 뒤 P003의 내경 분포(0.078 가정)를 E-CUBE 10명의 보정된 내경 분포와 비교한다. 정상 총경동맥 범위(약 6~8mm) 안에 들면 가정이 크게 틀리지 않았다는 참고 근거로 쓴다.
3. 두 방법 모두 확정이 아니므로, P003 결과는 `mm 참고값(보정 미확정)`으로 표시한다. **mm 성능 목표(내경 오차)는 E-CUBE 영상에서만 평가**한다.
4. 시험 대상자 P004가 E-CUBE 영상이라 최종 mm 평가에는 영향이 없다.

### 시간 축

DICOM 헤더에 `FrameTimeVector`(프레임별 간격)가 있다. 평균 약 37~39fps이지만 **간격이 12~52ms로 일정하지 않다.**

- 프레임 시각은 `FrameTimeVector` 누적값을 쓴다. 균일 fps로 가정하면 박동 주기(bpm)가 틀어진다.
- WMV(P001·P002)는 같은 검사의 DICOM 시각을 빌려 쓴다(프레임 수 일치 확인 후).
- AVI(P003)는 28.775fps 고정이다.

## 15. 평가 방법

### 데이터 평가

- 같은 사람의 영상은 한 묶음에 유지한다.
- 학습·검증·시험 배정은 6절의 `학습·검증 데이터 구성`을 따른다.
- 결과는 전체 평균과 함께 **사람별·그룹별(긴 DICOM / 3초 클립 / AVI)**로 제시한다.

### 교차검증 (필수)

**교차검증**은 검증 대상을 바꾸어 가며 여러 번 평가하는 방법이다. 검증 1명·시험 1명만으로는 그 1명의 결과가 전체를 크게 흔든다. 그래서 여러 사람 기준 성능의 평균과 편차를 함께 보고한다.

- 시험 P004를 뺀 10명으로 **9:1 순환**한다. P003은 유일한 AVI·ECG 영상이라 항상 학습에 두고, 나머지 9명(P001·P002·P005~P011)이 한 번씩 검증자가 된다 → 9회 학습·평가. 매회 학습 9명 : 검증 1명 비율이 본 실험과 같다.
- 확정된 설정 1개로만 돌린다. 설정 탐색은 기존 검증(P006)으로 끝낸다.
- 3초 클립(P001·P002·P009~P011)이 검증자가 되는 회차로 짧은 영상에 대한 처음 보는 사람 성능을 확인한다(6절 한계 보완).
- 결과: 9명 기준 Dice·HD95·내경 MAE·F 오검출률의 평균 ± 표준편차, 사람별 값, 그룹별(긴 DICOM / 3초 클립) 값

### 학습 곡선 (데이터 양 확인)

- 확정 설정으로 학습 라벨을 25%·50%·100%만 써서 학습한다. 줄일 때도 사람별 비율은 유지한다.
- 검증 성능이 50%→100%에서 거의 오르지 않으면 "데이터 양은 충분하다", 계속 오르면 "추가 데이터로 개선 여지가 있다"고 보고한다.

### 결과 해석 범위

- "11명, 장비 2종, 사실상 1개 기관의 예비 연구"로 범위를 한정한다.
- 다른 기관·장비에서도 같은 성능이 나온다고 주장하지 않는다.

### 변화량 평가

측정하려는 박동별 내경 변화는 약 0.5mm로, 내경 오차 목표(0.3mm)보다 크게 넉넉하지 않다. 내경 오차만으로는 변화량을 제대로 잡는지 알 수 없으므로 변화량을 따로 평가한다.

- 대상: 긴 영상 대상자인 시험 P004, 검증 P006
- 각 사람에서 박동 3~5개를 고르고, 박동마다 최소 내경 프레임과 최대 내경 프레임을 직접 라벨한다(사람당 6~10장).
  - 프레임은 내경 신호가 아니라 영상을 직접 보고 고른다(AI 결과의 영향 배제).
  - 시험·검증 라벨(9절)을 고를 때 이 프레임을 우선 포함해 추가 장수를 줄인다.
- 직접 잰 변화량(최대 − 최소)과 AI가 같은 박동에서 잰 변화량의 차이를 박동별로 계산한다.
- P003은 mm 보정이 미확정이라 변화량 mm 평가에서 제외하고, 박동 구분 검증(12절)에만 쓴다.
- 같은 영상 안에서 같은 방향으로 생기는 경계 오차는 최대 − 최소에서 상쇄되고, 여러 박동을 요약하면 무작위 오차도 줄어든다. 그래서 변화량 오차는 내경 오차보다 작을 것으로 예상하며, 이를 실제로 확인한다.

### 평가 지표

| 지표 | 의미 |
|---|---|
| Dice·IoU | 수동 마스크와 AI 마스크의 겹침 정도 |
| 내경 오차 | 수동 라벨과 AI 측정값의 차이 |
| 변화량 오차 | 같은 박동에서 수동으로 잰 변화량(최대 − 최소)과 AI 변화량의 차이 |
| HD95·평균 경계 거리 | 경계가 mm 단위로 얼마나 어긋났는지(11절 `검증 지표`) |
| F 오검출률·미검출률 | 검출 불가 프레임에 칠하지 않는지, 혈관이 있는데 놓치지 않는지 |
| 프레임 간 급변 | 동영상에서 결과가 흔들리는 정도 |
| 반복 라벨 Dice | 같은 사람이 라벨 기준을 일관되게 적용했는지 확인 |
| 전체 처리 성공 | 영상 입력부터 PDF 생성까지 작동 여부 |

- 전체 지표 목록과 보고서 표·그림 구성은 11절 `검증 지표`와 `보고서 산출물`을 따른다.

### Dice를 쓰는 이유

**Dice**는 AI 마스크와 정답 마스크가 겹치는 정도를 0~1로 나타낸다.

```text
Dice = 2 × 겹친 넓이 ÷ (AI 넓이 + 정답 넓이)
```

| 이유 | 설명 |
|---|---|
| 배경 착시 방지 | 화면 대부분이 배경이라 픽셀 정확도는 아무것도 안 칠해도 90% 이상이 나온다. Dice는 칠한 영역끼리만 비교한다 |
| 분할 표준 지표 | 의료영상 분할 연구에서 가장 널리 쓰여 선행연구와 비교할 수 있다 |
| 학습과 평가의 일치 | 손실함수(Dice+BCE)와 같은 기준으로 평가해 학습 목표와 평가 기준이 일치한다 |

**한계와 보완:** 혈관은 길쭉해서 경계가 1~2픽셀 어긋나도 Dice는 높게 나올 수 있다. 따라서 Dice로 1차 선별하고, 최종 선택은 **내경 오차(mm)**로 한다.

반복 라벨 검사는 의학적 정답을 증명하지 않는다. 선생님이 정한 기준을 일관되게 적용했는지 확인하는 용도다.

#### 추첨 기록 (2026-11-03)

새 대상자가 3명이 아니라 8명으로 늘어, 시험 1명 → **2명**, 검증에 1명 추가로 바꾸었다.

```python
import random
r = random.Random(20261103)          # 시드 = 추첨일
long_  = ["P004","P005","P006","P007","P008"]   # 긴 DICOM 그룹
short  = ["P009","P010","P011"]                 # 3초 클립 그룹
test_long  = r.choice(long_)                     # → P004
test_short = r.choice(short)                     # → P009
val_long   = r.choice([p for p in long_ if p != test_long])  # → P006
```

| 역할 | 결과 |
|---|---|
| 시험 전용 | **P004**, **P009** |
| 검증 추가 | **P006** (기존 P001과 함께 2명) |

- 그룹 정의와 시드는 결과를 보기 전에 정했고, 같은 코드로 누구나 같은 결과를 재현할 수 있다.
- 데이터 점검 과정에서 새 영상 대표 장면을 이미 보았으므로 "보기 전 추첨"은 아니다. 대신 품질을 기준으로 고르지 않았다는 점을 고정 시드로 보장한다.
- P004는 내강이 얇아 어려운 사례일 수 있다. 하지만 경동맥으로 확인되었고(2026-11-03) 재추첨 조건(경동맥 아님·파일 손상)에 해당하지 않으므로 **추첨 결과를 확정**한다.

#### 분할 변경 기록 (2026-11-10)

학습 9 · 검증 1 · 시험 1로 바꾸면서 새로 추첨하지 않고 기존 추첨 결과 중 **긴 영상 그룹 2명(시험 P004, 검증 P006)**을 남겼다.

- 기준은 품질이 아니라 영상 길이다. 변화량 평가에는 박동 10회 이상이 든 15초 영상이 필요하다.
- 기존 시험 P009와 검증 P001은 학습으로 옮겼다. P009 라벨은 처음부터 직접 그린 것이라 학습에 써도 문제없다.
