# 모델 선택: 최선 모델과 차선 모델

- 작성일: 2026-10-06
- 결정: **최선 = U-Net (ResNet34 사전학습 인코더)**, 차선 = HRNet-W18 (HRNetV2 분할 구조)
- 계획은 최선 모델로 확정한다. 차선 모델은 시간이 남을 때 같은 조건으로 비교한다.

## 1. 판단 조건

모델은 "논문에서 가장 높은 점수"가 아니라 **이 프로젝트의 조건**에서 고른다.

| 조건 | 내용 | 모델 선택에 주는 영향 |
|---|---|---|
| 장비 | MacBook Air M2, 통합 메모리 16GB, PyTorch MPS(Apple GPU) | 가볍고 MPS에서 문제없이 도는 연산만 쓰는 모델이 유리 |
| 시간 | 6주, 주 3시간 + α | 설치·디버깅이 적고 한 번에 학습이 성공해야 함 |
| 라벨 수 | 현재 3명: 시험용 A 약 60장. 예정된 6명: 초기 A 약 120장, 최종 A·B 약 240~300장 | 적은 라벨에서 일반화가 되는 **사전학습 모델**이 유리 |
| 사람 수 | 현재 동영상 3명(P001~P003) + 새로운 사람 3명분 재전달 예정. TIFF는 인터넷에서 가져온 불특정 다수의 자료이며 정확한 사람 수를 모름 | 과적합 위험이 큼 → 파라미터가 많은 모델은 불리. TIFF는 1차 학습·검증·최종시험에서 제외 |
| 측정 대상 | 위·아래 혈관 벽 사이 거리(mm), 박동에 따른 변화 | **출력 해상도**가 측정 정밀도를 직접 결정 |
| 영상 크기 | AVI와 WMV의 해상도·화면 눈금이 다름 | 공통 입력 크기로 변환하고 형식별 눈금 보정을 별도로 확인 |

마지막 두 조건이 핵심이다. 경동맥 지름은 약 6~8mm이고, 박동에 따른 지름 변화는 보통 **0.5mm 안팎**이다. 모델이 경계를 1픽셀만 틀려도 0.1mm 오차가 생기므로, **모델이 원본 해상도 그대로 경계를 예측하는지**가 중요하다.

## 2. 측정 결과 (같은 조건에서 직접 만들어 비교)

클라우드 작업공간의 CPU에서 두 모델을 실제로 만들어 측정했다. **절대 시간은 M2(MPS)와 다르고**, 두 모델의 상대 비교용이다.

| 모델 | 파라미터 수 | 학습 1스텝 (배치 8, 256×256) | 추론 1장 (352×288) | 예측 출력 해상도 |
|---|---:|---:|---:|---|
| **U-Net (ResNet34)** | 24.4M | **3.4초** | **264ms** | **입력과 같음 (352×288)** |
| HRNet-W18 (HRNetV2) | 9.6M | 7.4초 | 337ms | 입력의 1/4 (88×72) 후 확대 |
| HRNet-W48 (HRNetV2) | 65.8M | 9.3초 | 545ms | 입력의 1/4 (88×72) 후 확대 |

- HRNet-W18은 파라미터는 적지만 고해상도 줄기를 계속 계산하므로 **학습이 약 2.2배 느리다.**
- HRNet 분할 구조(HRNetV2)는 **입력의 1/4 크기에서 예측**한 뒤 늘려서 원래 크기로 맞춘다. 0.1mm/px 기준으로 예측 격자 한 칸이 **0.4mm**이고, 이는 측정하려는 박동 변화량(약 0.5mm)과 거의 같은 크기다.
- U-Net은 디코더가 원래 해상도까지 복원하고, 원래 해상도에 가까운 정보를 건너뛰기 연결로 직접 받아 **픽셀 단위로 경계를 예측**한다.

## 3. 최선 모델: U-Net + ResNet34 사전학습 인코더

### 선택 이유

1. **측정 정밀도에 맞는 출력 해상도**
   - 원래 해상도(0.1mm/px)로 마스크를 예측하므로 벽 위치를 0.1mm 단위로 얻는다.
   - 굵기와 박동별 변화량이 최종 결과이므로 가장 중요한 이유다.
2. **적은 라벨에 강함**
   - 인코더가 ImageNet으로 사전학습되어 있어, 경계·질감 같은 기본 특징을 처음부터 배울 필요가 없다.
   - 수백 장 수준의 라벨로도 학습이 안정적이다.
   - 흑백 1채널 입력도 라이브러리가 사전학습 가중치를 자동으로 변환해 준다.
3. **의료영상 분할의 검증된 표준**
   - 경동맥 초음파 분할 선행연구 대부분이 U-Net 계열을 쓴다.
   - 2024년 nnU-Net 연구진의 재검증(*nnU-Net Revisited*)에서도 잘 설정된 U-Net이 최신 Transformer·Mamba 계열과 같거나 더 나은 결과를 보였다.
4. **내 Mac에서 잘 돌아감**
   - 구성 연산(합성곱, 배치정규화, 업샘플링)이 모두 PyTorch MPS에서 지원된다.
   - 측정에서 HRNet-W18보다 학습이 약 2.2배 빠르다. 같은 시간에 더 많은 실험을 할 수 있다.
   - 24.4M 파라미터, 배치 8, 256×256 크롭이면 16GB 통합 메모리에 여유가 있다.
5. **구현 부담이 가장 작음**
   - `segmentation_models_pytorch` 라이브러리의 한 줄로 만들 수 있다.
   - 인코더 이름만 바꾸면 다른 백본과도 비교할 수 있다.

### 약점과 대응

| 약점 | 대응 |
|---|---|
| 파라미터 24.4M → 사람 수가 적어 과적합 가능 | 사전학습 사용, 데이터 증강, 조기 종료, 사람 단위 검증 |
| 전역 맥락은 HRNet보다 약할 수 있음 | 혈관은 화면의 큰 구조라 영향이 작을 것으로 판단. 결과가 나쁘면 차선 모델과 비교 |
| 프레임을 하나씩 처리 → 시간적으로 결과가 튈 수 있음 | 굵기 신호에 시간 방향 평활화와 급변 탐지(후처리) 적용 |

| nnU-Net Revisited (MICCAI 2024) | 엄밀한 비교에서 CNN 기반 U-Net이 Transformer·Mamba보다 우수하거나 동등 | 최신 구조 대신 U-Net을 고르는 근거 |
| He et al. (Sci Rep 2025) | 초음파 소량 라벨에서 ImageNet 사전학습 ResNet U-Net이 무작위 초기화보다 우수, 데이터가 적을수록 효과 큼 | 사전학습 인코더 사용 근거 |

## 4. 차선 모델: HRNet-W18 (HRNetV2 분할 구조)

### 차선인 이유

- **장점**
  - 고해상도 줄기를 끝까지 유지해 경계 정보 손실이 적은 구조다.
  - 2019~2020년 분할·자세 추정의 SOTA였다.
  - 사용자가 2021년에 분할 작업으로 사용해 본 경험이 있다.
  - 파라미터가 9.6M으로 적어 과적합 위험은 U-Net보다 작다.
- **최선이 아닌 이유**
  1. 표준 분할 출력이 **입력의 1/4 해상도**라서, mm 단위 굵기와 0.5mm 수준의 박동 변화 측정에 불리하다.
  2. 학습이 약 2.2배 느리다(CPU 측정 기준, M2에서도 비슷한 경향 예상). 주 3시간 일정에서는 실험 횟수가 줄어든다.
  3. 소량 라벨 의료 분할에서 U-Net만큼 검증 사례가 많지 않다.
  4. 분할 출력부를 직접 붙여야 한다. 약 20줄이지만 U-Net보다 구현과 검증 단계가 하나 더 있다.

### 차선 모델을 쓰는 경우

- 최선 모델이 **경계는 맞지만 혈관과 주변 구조(정맥, 근육 경계)를 혼동하는 실패**를 반복할 때. 전역 맥락이 필요한 문제로 판단한다.
- 일정에 여유가 생겨 "모델 선택 이유"를 실험으로 보이고 싶을 때. 같은 데이터 분할과 같은 학습 설정으로 한 번 비교한다.
- 해상도 약점을 줄이려면 1/4 출력 위에 업샘플링 디코더를 추가할 수 있다. 다만 구조가 U-Net에 가까워지므로 우선순위는 낮다.

## 5. 검토했지만 제외한 모델

| 모델 | 제외 이유 | 남겨둘 용도 |
|---|---|---|
| HRNet-W48 | 65.8M 파라미터로 데이터 대비 과도함. 출력은 W18과 같은 1/4 해상도 | GPU 서버에서 참고 비교 |
| nnU-Net | 기본 학습이 1,000 epoch × 5-fold라 Mac에서 수일 소요 | 설정 방식(증강, 손실, 학습률)만 차용. GPU 서버에서 참고 비교 |
| SAM / MedSAM | 점·상자 입력이 필요하고 무거워 전체 프레임 자동 추적에 부적합 | **라벨링 보조**(초안 생성)용 |
| 동영상 분할 모델 | 구조가 복잡하고 라벨·연산 부담이 큼 | 범위 밖. 시간 일관성은 후처리로 해결 |

## 6. 확정 학습 설정 (최선 모델)

| 항목 | 값 | 근거 |
|---|---|---|
| 모델 | `smp.Unet("resnet34", encoder_weights="imagenet", in_channels=1, classes=1)` | 위 3절 |
| 전처리 | 화면 텍스트 제거 크롭 → 흑백 → **0.1mm/px로 재표본화** → 밝기 정규화 | 장비가 달라도 혈관이 같은 크기로 보이게 함 |
| 학습 입력 | 256×256 무작위 크롭 | M2 메모리 여유, 혈관 지름 약 70px가 크롭 안에 충분히 들어감 |
| 추론 입력 | 영상 전체(가로·세로를 32의 배수로 패딩) | 모델이 크기와 무관하게 동작하므로 화면 전체를 한 번에 처리 |
| 손실함수 | Dice + BCE | 작은 영역 분할 표준 |
| 최적화 | Adam, 학습률 1e-3, 점진 감소(poly 또는 cosine) | 표준 시작값 |
| 배치 | 8 | 메모리 기준 |
| Epoch | 최대 100, 검증 Dice 10회 정체 시 조기 종료 | 과적합과 시간 낭비 방지 |
| 증강 | 밝기·대비·감마, 좌우 반전, 약한 크기 변화(±10%)·회전(±10°) | 장비 차이와 탐촉자 각도 차이를 흉내 냄 |
| 샘플링 | 사람을 먼저 고르고 그 사람의 프레임을 고르는 균형 추출 | P003이 프레임의 대부분을 차지하는 불균형 대응 |
| 장치 | `mps`, 안 되면 `cpu`로 자동 전환 | Mac 실행 |
| 평가 | 학습에 쓰지 않은 사람의 Dice, IoU, 굵기 오차(mm) | 계획서 8절 |

### Mac에서 확인할 것 (첫 학습 때)

- MPS로 학습이 끝까지 오류 없이 도는지(`PYTORCH_ENABLE_MPS_FALLBACK=1` 설정)
- 1 epoch 소요 시간 → 전체 학습 시간 추정
- 메모리 사용량(활성 상태 보기). 부족하면 배치를 8에서 4로 줄임
- 동영상 1개(약 2,200프레임) 추론 시간 → 앱 사용성 판단
